# v3.1.0

v3.0.8からの互換minor更新です。実装や画面の枠が既にあることではなく、その仕組みがないと何が困るかを出発点に、提案・実装・審査するようになりました。

- [設計判断](https://github.com/natumekazuki/opencode/blob/5346007cfd8879d4bd5a3c262be0d9b416b15d82/docs/guides/design-decisions.md)では、責務そのものを外せるかを検討します。必要ならフロント・バックそれぞれで既存の担当箇所を使い、同じ業務判定の分散を防ぎます。所有者の異なる処理や使い捨ての検証まで共通化することは求めません。
- [UIガイド](https://github.com/natumekazuki/opencode/blob/5346007cfd8879d4bd5a3c262be0d9b416b15d82/docs/guides/ui.md)では、補助用の空枠を先に作りません。配置・既存ラベルで意味が通じず、新たな補助説明が必要な場合は、対象と状態、最短の文案と理由を差分単位で示し、実装前に明示承認を受けます。一語のバッジやツールチップでも役割が同じなら対象です。本文・操作名・読み上げ・安全確認・失敗からの回復は機能自体として残します。
- [報告](https://github.com/natumekazuki/opencode/blob/5346007cfd8879d4bd5a3c262be0d9b416b15d82/AGENTS.md)では、結果と受入判断に必要な制約を伝えます。依頼外で行わなかったことを列挙する必要はありません。[変更test](https://github.com/natumekazuki/opencode/blob/5346007cfd8879d4bd5a3c262be0d9b416b15d82/docs/guides/test-changes.md)も、消した旧実装の不在だけを恒久化せず、認可など現在も必要な契約を守るものを残します。
- [Session間の協同](https://github.com/natumekazuki/opencode/blob/5346007cfd8879d4bd5a3c262be0d9b416b15d82/docs/guides/withmate-collaboration.md)と[作業領域](https://github.com/natumekazuki/opencode/blob/5346007cfd8879d4bd5a3c262be0d9b416b15d82/docs/architecture/subagent-workspace.md)は、実呼出元への相談、直属親への保存後配送、再開時の条件復元を使い分けます。OpenCodeのnative子を使わない方針と、変更test全件の独立審査は従来どおりです。

## 利用・互換性・移行

Skill名・配置、設定例のモデル・権限、抽出CLI・結果・metadataの形式は変わりません。設定・認証・履歴の移行は不要です。直接checkoutしている端末では既存のローカル変更を保って更新し、新しいOpenCode Sessionから使います。手動配置では入口だけでなく、ガイド・対応する同梱Skill・agent定義を[配置手順](https://github.com/natumekazuki/opencode/blob/5346007cfd8879d4bd5a3c262be0d9b416b15d82/README.md#配置と導入)に従って同じ版に揃えてください。WithMateのmanaged SkillとSession-bound MCPは引き続きhostが供給します。
